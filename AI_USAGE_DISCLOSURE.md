## 2. Generative AI inside the product, at run time

One component calls a model when the service handles a request.

| | |
|---|---|
| **Component** | `extract()` — `backend/extract/pipeline.py`, exposed via `app/extractor.py` |
| **Model** | Google Gemini, `gemini-3.5-flash-lite` primary, with `gemini-3.8-flash` and `gemini-3.1-flash-lite` as fallbacks (`backend/extract/client.py`) |
| **What it does** | Converts a Samsung SIIS support document plus a user complaint into goals → actions → step groups |
| **SDK** | `google-genai==2.25.0`, JSON response mode, temperature 0 |

The model chain was chosen by measurement, not preference. Probing the account's own model
list with two attempts each found three of six models returning HTTP 503 "high demand", and
`gemini-3.5-flash` taking 26 seconds on the one attempt that answered. The full table is
recorded in `backend/extract/client.py`.

### What the model is *not* allowed to do

This is the core design decision of the project, and it is a constraint on the model rather
than a capability of it:

- **It never emits a deeplink URI, and is never shown one.** The catalog is matched *before*
  the model is called; the model receives a numbered list of plain-English labels containing
  no URI and not even a catalog id, and answers with an index or `null`. The server maps
  that index back to the catalog entry. A hallucinated deeplink is therefore structurally
  impossible rather than something caught afterwards (`backend/extract/candidates.py`).
- **Its steps must trace back to the supplied document.** Every generated step is checked
  against the source text and dropped if it cannot be traced, which is what stops the model
  answering from its own knowledge of Samsung devices (`backend/extract/grounding.py`).
- **Its formatting is never trusted.** Output goes through `sanitize()` then `validate()`
  regardless, and the regex-critical `goal` sentence is constructed by our code from a short
  name the model supplies, so that string is never at the mercy of model formatting.
- **It is never required.** If Gemini errors, times out, returns unparseable JSON, fails
  validation twice, or produces nothing groundable, a deterministic no-LLM fallback builds a
  plan from the document's own headings (`backend/extract/fallback.py`). The service never
  returns an empty response.

## 3. Generative AI used at build time, then human-checked

Data generated by a model offline and then verified before being committed.

| Artefact | Generated by | How it was checked |
|---|---|---|
| `fixtures/paraphrases.json` — 162 query paraphrases across the 20 kit queries | Gemini via `app/variations.py` | Counts asserted in range 8–10, uniqueness and no-echo asserted, lexical diversity measured; used as the cache's paraphrase test set |
| `testdata/unseen_siis.json` — 8 unseen SIIS payloads for generalization testing | Written by hand with AI assistance | Verified to contain no URLs, to duplicate no kit document, and to parse into ≥3 sections each |
| `docs/KIT_NOTES.md`, `docs/PLAN.md` | Drafted with AI assistance | Every factual claim re-derived from the kit files directly |

`app/variations.py` also contains a deterministic, no-LLM paraphrase generator used whenever
Gemini is unavailable, so the test suite needs no API key.

## 4. Designed, measured and verified by hand

These are the parts a reader should judge the project on. They were not model-generated
designs — they are decisions made from measurements taken against the provided kit, with the
numbers recorded next to the code.

**The deeplink matcher** (`backend/matcher/`). The two-signal gate exists because neither
signal works alone, and that was measured rather than assumed: lexical similarity scores a
*false* positive at 0.279 while scoring a *true* positive at 0.166, and semantic similarity
leaves a 0.003 gap between its weakest true positive and strongest false positive. The
shipped thresholds (semantic ≥ 0.77, grounding ≥ 0.60) come from a sweep over 38
hand-labelled SIIS sections, and the operating point is the *midpoint* of the safe plateau
rather than its edge. Result: precision 1.000, recall 0.800, abstention 1.000.

**Polarity resolution** (`backend/matcher/polarity.py`), because 111 settings — 222 entries,
38% of the catalog — exist as both "Enable X" and "Disable X" with *identical*
`qna_description`. No embedding can separate them, so direction is resolved from the step
text; without this the right setting comes back with the wrong direction about half the time.

**The grounding threshold** (`backend/extract/grounding.py`) was calibrated against 83
genuinely-copied steps and 7 plausible *invented* Samsung instructions. 0.65 is the lowest
value that leaked none of the seven, and the code states honestly that the 83 real steps pass
on containment and therefore say nothing about the paraphrase tier.

**The cache similarity threshold** (`app/cache.py`) went through two revisions, each forced
by checking the previous number against real data. It shipped at 0.85: the measured collision
ceiling between distinct graded kit rows is 0.8435, and 0.85 gives an 86.4% correct-paraphrase
rate against an 80% target with zero collisions.

**Things found only because a claim was checked, not trusted:**

- The kit's `siis_responses.json` states its text is "pre-cleaned: no URLs or images". It is
  not — rows 3, 11 and 17 contain `kidshome.pin@samsung.com`.
- Our own URL detector returned **False** on all three of those rows. It had a trailing word
  boundary, and the kit writes the address run-together as `samsung.comusingyour…`, so there
  was no boundary to match. The tests had passed only because the catalog itself is clean, so
  the detector had never been exercised against a real leak.
- The catalog's `message` field is frequently misleading. `DL-0022` reads "View Reset Options"
  but means auto-reset after failed unlock attempts; there is no factory-reset entry at all,
  yet the embedding scores it 0.787 against a factory-reset step. "Disable Charging" means
  vibration feedback while charging.
- `student_kit/sample_output.json` violates the stated 5–7 word description rule (its
  descriptions are 9 and 12 words) and omits the trailing period its own goal regex requires.
- `fastembed`'s `query_embed` returns vectors identical to `embed` for this model, so the BGE
  retrieval prefix is applied by our code.
- A dependency commit pinned "the verified versions" to versions that were never verified.

**Also hand-built:** the strict validator (`app/validator.py`), the sanitizer, the verbatim
catalog→schema projection, the gate-scoring harness (`scripts/run_harness.py`), the
deterministic fallback, the demo page, and the Docker packaging.

## 5. Testing

**487 automated tests**, all passing. The default suite is fully offline — the LLM client is
injected, so it runs with no API key and no network, which is what lets a judge run it on a
clean machine. A separate set of 28 tests exercises real Gemini and is skipped unless
`BIXEL_LIVE_LLM=1`; those were run manually and pass.

Tests were written with AI assistance. Several of them failed on first run and the cause was
the *test*, not the code — near-identical synthetic queries that correctly hit the cache, a
fresh fake client per request replaying a 503, an empty list treated as falsy. Those
corrections are recorded in the commit history rather than quietly fixed, because a test
suite is only worth what its failures taught.

## 6. Honest limitations

- The `bixby://` URIs are Samsung's **masked placeholders**. Deeplinks are copied
  byte-for-byte from the supplied catalog and never constructed, but they do not launch a
  real Bixby action. The demo page says so on screen rather than faking a launch.
- Deeplink coverage is low — about 2 of 35 step groups. That is close to the ceiling the
  catalog allows: the matcher can offer a candidate for only 10 of 90 sections, because the
  catalog is Settings toggles while these documents mostly instruct physical actions and
  support escalation. Raising it would mean attaching wrong deeplinks.
- The gate thresholds we test against are reconstructed from the brief, not an official
  rubric. They are our own QA floor.
- An uncached request takes roughly 7 seconds end to end, because it pays a real Gemini call.
  Repeat and paraphrased requests are served from cache in about 20 ms.
